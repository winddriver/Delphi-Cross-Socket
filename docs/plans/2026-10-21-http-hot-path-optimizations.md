# HTTP 热路径四项优化

状态：实施中。基线：97ce754，开始时工作区干净。

## 目标与边界

按用户确认的顺序逐项优化，每项独立回归、独立性能对比、独立本地提交。
保持现有头体分离发送机制；不改发送队列、TLS、IOCP、关闭及完成回调策略，不推送。
公开接口签名、字段解析语义、路由动态更新和请求对象生命周期保持兼容。

## 步骤与涉及文件

- [x] P1：`Net/Net.CrossHttpParams.pas` 的 ContainsToken 改为直接扫描，避免枚举器、Split、Trim 的临时分配。
  - 验证大小写、重复字段、空 token、逗号、空白、非法 ASCII/Unicode 字符、完整 token 匹配；与旧算法差分比较。
- [x] P2：同单元 GetHeaderValues 在没有匹配字段时不分配数组。
  - 验证无匹配、空值、重复字段顺序、大小写、调用前输出数组已有内容；测量无匹配及多匹配场景。

  - 更新路由时生成独立数组，请求在既有锁内取得引用；不得修改正在执行的快照。
  - 验证处理顺序、Handled/Sent 短路、回调中注册处理器、并发更新/执行、闭包引用释放。
- [ ] P4：同单元 Cookies、Params、Query 按需创建。
  - 检查所有直接字段访问；有数据时保持解析/发布时机，空容器在首次访问时创建。
  - 验证空请求、实际 Cookie/查询/路由参数、重复 getter、并发首次读取、请求保留和关闭后的读取、清理。

新增专项测试目录 `Net/Tests/FPC/HttpHotPathTests/`，沿现有 Pascal 测试及 Python 构建脚本约定实现。

## 验证方式

1. 每项先补行为用例并构建未优化基线，再修改实现；Delphi Win64/Win32、FPC Win64 运行回归。
2. 每项将同一测试程序分别链接修改前后源码，Release/优化开启；预热后交替运行至少五轮，报告中位数及离散范围。
3. 时间与分配分别测量；微基准用于确认目标操作收益，不能当成服务端 RPS 的同比提升。
4. 复用 HTTP 失败/发送策略、请求生命周期、认证等相关既有测试；完成后正式 HttpServer Release/Win64 构建。
5. 用 FastMM5、65 个 I/O 线程、1000 并发的 HTTP GET 回环做累计端到端对比；头体保持两次发送，正文及头长度一致，必须零失败。
6. 若收益不稳定，明确记录；若有回归或兼容边界未解决，不把该项标为完成。
7. Pascal 文件保持 UTF-8 BOM；每次提交前检查状态、差异、编码和发送路径未变。
