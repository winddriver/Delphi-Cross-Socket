# O06 首批缓冲基准与取舍（2026-10-19）

最终只保留 WebSocket 编码时清零帧头的单行优化。TLS 空 BIO 提前返回候选因 Delphi 大块读取的稳定延迟回退未采用；SSL 生产源与基线相同。没有引入缓冲复用、所有权转移或新开关。

## 方法与边界

- 基线是已包含 F12 与托管队列修复的 `65a5df2`，两生产单元快照位于 `bin/o06-before/production/`；不是旧 WS 重构前版本。脚本按该提交导出并校验快照，不切换工作区。
- Windows x64：Delphi 13.1 显式 `-$O+`，FPC 3.3.1 显式 `-O2`。基准线程绑定 CPU 掩码 2；QPC 频率 10 MHz（100 ns 一 tick）。每负载先预热 128 次；两版交替五轮，奇数轮先前版、偶数轮先后版。
- WS 计时窗口直接调用 MakeFrameData，含真实 CSPRNG 掩码生成、分配、头部编码和载荷复制/XOR；没有使用在构帧之后才启动计时的旧解析基准。无 mask 与真实随机 mask 分列，不能把无 mask 收益套用到客户端随机掩码负载。
- 批次平均耗时、单次延迟和分配统计是三个独立 pass。计时 pass 未安装内存管理器钩子；计数 pass 用原生 GetCurrentThreadId 过滤到基准线程，排除连接的后台 I/O 线程。
- 分配数为 Pascal GetMem/AllocMem 和正大小 ReAllocMem 的调用数；申请字节是这些调用参数的累计值，重分配按完整请求长度计。它不是实际新增字节、峰值内存或 OpenSSL/CSPRNG 原生堆占用。后几项未测，不报推算值。
- 表中 ns/op 是每轮整批耗时除以次数后，五轮的中位数；括号为 inclusive 四分位距 IQR。P99 是每轮单次本地调用加 QPC 测量开销的 nearest-rank P99，再取五轮中位数；不是网络 P99。小包常落在一个 100 ns tick，不能据此宣称尾延迟改善。大包每轮至少 512 次，尾部样本有限。
- 每种大小/掩码组合在计时前后逐字节校验头部长度与解掩码后的载荷，并保留旧 TBytes、构造不同 FIN/opcode 的后续帧后确认旧内容不变；随机 key 不要求两次生成相同，而要求每个实际 key 对应的帧解码一致。
- 原始五轮样本及每项 P99/IQR 在 `bin/o06-ws-final-results/{win64,fpc64}.json`；对应二进制、构建参数、源哈希和逐轮日志在 `bin/o06-ws-final-{before,after}/`。初步未显式固定优化等级的 `bin/o06-results/` 不用于以下结论。

## 未采用的 TLS 候选

候选仅在 `_BIO_read_all` 开始把 Result 设 nil，并在 BIO_pending 为零时返回。真实 TLS 1.2/1.3 会话先生成具有连续记录序号的密文，握手、预生成及预热不在计时内；测试窗口只调用真实 Inject/SSL_read 和计数接收回调，不走内核网络。32 B、1 KiB、64 KiB 分别统计，没有把不同大小混为一个均值。

最初显式优化构建的完整五轮时间记录在 `bin/o06-optimized-results/`。这些时间 pass 没有内存钩子；当时分配 pass 尚为进程级计数，可能受后台线程污染，因此其分配值不纳入最终收益表。以下完整保留两编译器的时间结果：

### Delphi 大块读取独立复核

针对初测回退另做十轮交替，使用同一已构建二进制，只运行 TLS 负载；原始值保留在 `bin/o06-optimized-results-tls-recheck/win64.json`。

| TLS / 64 KiB | 前 ns/op（IQR） | 后 ns/op（IQR） | 耗时变化 |
| --- | ---: | ---: | ---: |
| 1.2 | 22833.50（599.61） | 23836.43（646.92） | +4.39% |
| 1.3 | 24150.10（797.66） | 26492.38（2756.10） | +9.70% |

这个 4%–10% 回退没有被当作噪声或默认接受。进一步转发真实 BIO_ctrl 的探针显示：两版在两种 TLS 版本、三种载荷下，每 100 次普通接收都只有 100 次 pending 查询，非空次数均为 0；因此非空路径的额外查询不能解释本负载的回退。未做采样 profiler，不猜测具体 heap/cache 根因。候选已撤回，不为掩盖回退加入开关或缓冲框架。

候选源码在 `bin/o06-tls-candidate-source/`；探针二进制和日志在 `bin/o06-probe-{before,after}/win64/`。最终 WS 对照两版的 SSL 源哈希完全相同，避免把未采用的 TLS 改动混入最终收益。

## 重跑最终 WS 对照

```powershell
python -B run_buffer_bench.py --build before --targets win64 fpc64
python -B run_buffer_bench.py --build after --targets win64 fpc64
python -B run_buffer_bench.py --compare --rounds 5 --targets win64 fpc64 --modes bench-ws
```

工作目录为本目录。脚本复用已有工具链和本地测试证书，不安装依赖、不修改全局设置。证书路径使用 `bin/managed-final3/win64/`，缺失时先按 README 的 TLS 回归命令生成。性能只测 Windows x64；Linux、Win32 和其他 OpenSSL 版本用于正确性，未推导它们的性能。没有测慢消费者、端到端吞吐、峰值内存或事件系统调用次数。

最终正确性结果与依赖版本见 README 和 `bin/o06-final-manifest.json`。
